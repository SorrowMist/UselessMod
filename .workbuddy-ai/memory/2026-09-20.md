## 造化杖无法挖掘「自定义挖掘等级」方块（ATM 三矿）—— 已修

### 根因（字节码实证）
- 造化杖 = `useless_mod:endless_beaf_item`，类 `EndlessBeafItem extends TieredItem`，7 个变体。
- `createProperties()` 的 TOOL 组件**第一条规则**是
  `Tool.Rule.deniesDrops(Tiers.NETHERITE.getIncorrectBlocksForDrops())`。
- 原版 `net.minecraft.world.item.component.Tool.isCorrectForDrops()` 语义 =
  **按顺序遍历规则，返回第一条命中的 correctForDrops；全不命中返回 false** ⇒ 首位 deniesDrops 即一票否决。
- ATM 的数据包把 `#c:needs_allthemodium_tool / needs_vibranium_tool / needs_unobtainium_tool /

- 调用链（javap 验证）：`Player.hasCorrectToolForDrops(BlockState)` → `ItemStack.isCorrectToolForDrops`

  `EventHooks.doPlayerHarvestCheck` 也只是先调它再发 `PlayerEvent.HarvestCheck`。
- 连锁路径同源：`MiningUtils.canMineBlock`（`:112`）委托 `tool.isCorrectToolForDrops(state)`。

## 【重要修正】造化杖「挖不动」的真正根因 —— 是两个独立 bug，不是一个

用户反馈「还是挖不动」后拿到 ATM/ATO 源码（`references/AllTheModium-1.21.x`、`references/AllTheOres-1.21`）复查，
发现之前的结论**只对了一半**。

### bug A（掉落）—— 之前已修
`deniesDrops(#incorrect_for_netherite_tool)` 一票否决 → `hasCorrectToolForDrops=false` → 方块被移除但不掉落。
影响：ATM 的 vibranium/unobtainium 矿 + ancient_stone 系列（`c:needs_*_tool` 并入 incorrect 标签）。

### bug B（挖不动）—— 本次新发现，**这才是「挖不动」的直接原因**
ATM 的方块用 `strength(-1.0f, X)` 声明 **硬度 = -1**（原版语义 = 基岩级不可破坏），
再靠**重写 `getDestroyProgress`** 让自己可挖：

```java
// Allthemodium_Ore / Vibranium_Ore / Unobtainium_Ore / AncientStone 都是这个套路
Properties.of().requiresCorrectToolForDrops()...strength(-1.0f, 1500f/2500f/5000f)
// 自写进度：
if (canEntityDestroy(state,getter,blockPos,player)) {
    int i = player.hasCorrectToolForDrops(state, player.level(), blockPos) ? 250 : 1500;
    return player.getDigSpeed(state, blockPos) / 2.0F / i;
}
return 0.0F;
```

而造化杖的 `getDestroySpeed` 里有 `if (hardness < 0) return 0.0F;`
→ `Player.getDigSpeed` 归零 → ATM 那套自写进度恒为 0 → **方块完全挖不动**。

**修复**：`hardness < 0` 时改为 `return baseSpeed;`（把"能不能挖"的判定权交回方块自身）。
**为什么不会把基岩变成可挖**（字节码确认）：`BlockBehaviour.getDestroyProgress` 在
`destroySpeed == -1` 时直接 `return 0.0F`（偏移 11–19 的 `fcmpl -1.0f; ifne; fconst_0; freturn`），
压根不会用到我们给的速度。只有**自己重写 getDestroyProgress 的方块**才会受影响 —— 正是想要的效果。

### 排除的其他可能性（都验证过）
- `events/PlayerHarvest.java`：**整个类体被 `/* */` 注释掉**，ATM 没有订阅 `PlayerEvent.HarvestCheck`。
- `allthemodium.mixins.json`：`"mixins": []` 为空，只有两个 **client** mixin
  （`MixinLocalPlayer` 是盾牌、`HarvestToolProviderMixin` 是 Jade 提示框显示），**无 common/server mixin**。

- `canEntityDestroy`：NeoForge `IBlockExtension` 默认实现对非末影龙实体返回 **true**，不是阻塞点。
- **ATO 完全无关**：矿材料只有铝/镍/铂/铀等 17 种常规金属，`strength(3.0F, 3.0F)` 正常硬度、

### 后续：用户反馈「能挖了但速度非常慢」→ 加 beef_tool_pseudo_hardness
根因：ATM 四类方块（3 矿 + AncientStone）的自写进度公式**完全一致**：
`player.getDigSpeed(state,pos) / 2.0F / (hasCorrectToolForDrops ? 250 : 1500)`。
- 造化杖挖普通方块：`progress = baseSpeed×hardness / (hardness×30) = baseSpeed/30 ≈ 0.333/tick`（约 3 tick）
- 造化杖挖 ATM 矿：`progress = baseSpeed / 2 / 250 = baseSpeed/500`，baseSpeed=10 时只有 0.02/tick（约 50 tick）→ 慢 17 倍

修复：`hardness < 0` 时不再返回 `baseSpeed`，而是 `baseSpeed × beef_tool_pseudo_hardness`（新配置，默认 **15**）。
- 15 → `(10×15)/500 = 0.30/tick ≈ 3.3 tick`，与普通方块手感一致
- 30 → 0.6/tick ≈ 1.7 tick；60 → 1.2/tick（被钳到 1.0，即 1 tick 秒破）
- 语义：用「名义硬度」替代哨兵值 -1，让 `baseSpeed × 硬度` 这条公式继续成立
